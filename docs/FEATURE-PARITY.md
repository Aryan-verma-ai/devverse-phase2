## 1. Overview and Legend

This matrix maps every existing DevVerse Phase 1 destination and feature to its data source, intended Phase 2 behavior, migration tier, and concrete acceptance test.

### Migration Tiers (from SYSTEM-DESIGN.md)
* **Tier 1 (Foundation & Project Slice):** App shell, design tokens, navigation, Explore, Project Detail, Submit Project, GitHub import, project persistence.
* **Tier 2 (Identity & Portfolio):** Server auth (signup/login/logout/me), Profile, Portfolio Builder/Viewer, Settings, authorization rules.
* **Tier 3 (Interaction & Collaboration):** Likes, bookmarks, Communities, Forum threads/replies, Squads, Join requests.
* **Tier 4 (Events, Learning & Gamification):** Hackathons, Registrations, Codex knowledge base, Leaderboard, Dashboard activity.
* **Tier 5 (Hardening & Delivery):** Validation, error states, accessibility/responsive checks, automated test suites, documentation.

### Data Source Classification
* **Seed:** Static in-memory mock objects/arrays (`js/data.js`).
* **localStorage (namespaced):** Browser `localStorage` split into global (`devverse:v1`) and per-account (`devverse:v1:user:<email>` / `devverse:v1:guest`).
* **Simulated:** Client-side timeouts, pseudo-random generators, or mock algorithms without server interaction.
* **External API:** Live public third-party REST API (`api.github.com`).
* **Phase 2 Backend (Target):** Node/Express REST API (`/api/...`) backed by MongoDB + Mongoose.

## 3. Scope Boundaries & College-Project Constraints

Per [SYSTEM-DESIGN.md](file:///c:/Users/acer/OneDrive/Desktop/DevVerse/SYSTEM-DESIGN.md) Section 3, the following are explicitly **out of scope** (avoided or simplified):
1. **No Microservices or Kubernetes:** Single Express API serving client and endpoints.
2. **No WebSockets / Real-time Socket Server:** Discussion boards, notifications, and squad requests use standard REST polling or direct page updates. The 1:1 chat from Phase 1 remains simulated client-side or maps to async squad join requests.
3. **No External Mail / Email Delivery:** Registration does not require external SMTP / email verification tokens.
4. **No Complex ML Recommendations:** Explore sort/filter uses deterministic queries (likes, views, createdAt, category, difficulty).
5. **No Production Payment Gateways:** Hackathon prize pools are informational; no payment rails.
6. **No Fake Activity Presented as Live:** The home page procedural activity ticker and profile random heatmaps will either be driven by real database activity records or explicitly badged as "Sample Activity / Demonstration Mode".

| **External GitHub API Rate Limits** | `api.github.com` unauthenticated requests are limited to 60 requests/hr per IP. | Retain graceful fallback: if GitHub API returns 403 (rate limited) or 404, fall back to manual form entry with clear status text. |
